# Dev Log — Day 1 (12 November 2026)

Solo developer, working with Claude Code connected to the Unreal Editor through
the official Unreal MCP plugin. All gameplay code is C++ written by the AI agent
and read by me in Rider. This log is reconstructed from the git history and the
session checkpoint on Day 2; nothing here is from memory alone.

## How the theme was approached

The theme is **Director's Cut**. The first decision was to make it a mechanic and
not only a costume. Two layers were chosen:

1. **Pre-run editing.** Before each run the player slots "scene cards" into film
   slots. The cards decide which horde, elite or boss appears, and raise the
   payout multiplier. Difficulty comes from the player's edit, not from dice.
2. **The Editing Room.** A camp building that "restores cut footage", which
   unlocks new cards and weapons.

A draggable timeline editor was considered and rejected: the UI cost is too high
for four days. Card slots give the same decision with a fraction of the work.

## The game on a sticky note

> Fantasy top-down horde survival. Slot cards before the run to set the
> difficulty. The more treasure you carry, the stronger the monsters — use it to
> survive, or carry it out to build the camp.

The base is a known genre pairing: survivors-like combat plus extraction-style
loot. The intended twist is **heat**: every rare item in the bag makes enemies
stronger, and every relic can be burned on the spot for a buff that also lowers
heat. So each pickup asks "keep it or use it?".

## What was done

| Step | Result |
|---|---|
| Scope | A requirements plan, then a master PRD with Must / Should / Could tiers and fixed cut rules, plus 11 per-system design docs. |
| Project | A new Unreal Engine 5.8 C++ project, created after the jam started. Only tooling and agent configuration existed before. |
| Story 001 | Loot bag, heat, relics, supply containers. |
| Story 002 | Extraction zones, run outcome, death (lose the whole bag). |
| Story 003 | Auto-attack weapon, health, one enemy type, spawn scheduler, greybox map. |
| Data | All tuning values live in four DataTables, not in code. |

Everything is greybox: cubes and capsules only, by design, until the loop works.

## How the AI was used

- **Planning first.** The agent wrote the plan and PRDs with me before any code.
  The master PRD is the "scope gate": a new feature has to be given a tier there
  before it can be built.
- **Stories.** Each story is a small slice with acceptance criteria. The agent
  implements it, builds, runs the game in the editor, and keeps screenshots as
  evidence in `production/qa/evidence/`.
- **MCP.** The agent drives the editor directly (creating assets, placing actors,
  starting Play-In-Editor) instead of telling me which buttons to press.

## What went wrong

- **The hero could not die.** The death handler was missing its `UFUNCTION`
  marker, so the delegate binding silently failed. It compiled and looked fine;
  it was only caught by actually playing until health reached zero. Lesson: a
  successful build proves nothing about gameplay.
- **Project move.** The project had to be migrated to a UE 5.8 editor project
  mid-day, which left stale paths in the config and the README.

## Not done

- **No playtest with other people.** The Day 1 exit criterion was "keep it or use
  it has been tested with 1–2 people". That did not happen.
- No art, no audio.
